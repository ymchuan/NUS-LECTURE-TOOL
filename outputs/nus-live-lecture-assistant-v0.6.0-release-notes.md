# NUS 课堂同传 v0.6.0

## 延迟排查结论

- 原阿里方案使用北京区域 `paraformer-realtime-v2`，NUS 到北京的跨区域网络会增加往返时间。
- 原设置需要约 650 ms 静音才结束一句，并启用了多阈值断句；短句通常需要更久才稳定输出。
- 每个音频块曾被展开成整数数组后再经过一次串行桌面进程调用，带来不必要的编码与通信开销。
- 界面只展示服务端结果，不是渲染防抖造成的等待；阿里增量结果本来就会即时显示。

## 本次改进

- 阿里实时转写默认升级为新加坡 `qwen-audio-3.0-asr-flash-streaming`，保留北京 Paraformer 低成本选项。
- 静音断句由 650 ms 调整为 300 ms，并关闭多阈值断句，优先保证交互速度。
- 音频改用 Base64 二进制批次穿过 Tauri 边界，避免把 PCM 展开成大型 JSON 数组。
- 课程术语作为即时热词发送给 Qwen Audio 3，提高专业词汇识别率。
- 实时记录区新增“首字”指标：低于 1 秒显示绿色，1 至 1.8 秒显示黄色，更高显示红色。
- 已保存的旧阿里 Paraformer 默认配置会一次性迁移到 Qwen Audio 3；用户仍可手动切回。

## 延迟目标说明

- “1 秒内”针对英文首个增量文字，而不是完整句子、中文翻译或总结。
- 最终英文需要等待老师停顿和断句，中文翻译在最终英文之后调用文本模型，因此会比首字更晚出现。
- 新加坡 Qwen Audio 3 官方参考价为 CNY 0.00066/秒，约 CNY 2.376/小时；北京 Paraformer 约 CNY 0.864/小时。

## 验证

- 新加坡实时 WebSocket 已使用现有 Keychain 配置成功建立并收到任务启动确认。
- TypeScript、Vite、Rust 单元测试和 macOS release 构建通过。
- 桌面设置页、实时记录页和首字状态已在 release 应用中检查。
- 自动化环境的系统播音不会被内置麦克风回采；课堂声学环境下的首字实测需在应用内对着麦克风说话，以界面指标为准。
